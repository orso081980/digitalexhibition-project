      The application

      How the app works

      Editors keep working in WordPress. The Nuxt application reads that content through the WordPress REST API and shows it in a different layout. Images are not copied: all three sites use one shared bucket.

      From edit to visitor, step by step

        Why the manual “Press Deploy” step? It saves API calls. On a server-side-rendered website every visit would call WordPress, and that can be costly. Here WordPress is called once per deploy instead.

        Jamstack in practice

        REST API & Jamstack

        Jamstack means the site is built ahead of time instead of being assembled on every visit. WordPress becomes a content source, and the visitor never touches it.

        JavaScript

        Nuxt (Vue) and Tailwind draw the layout.

        APIs

        The WordPress REST API supplies the content. Brevo handles the contact form mail.

        Markup

        Every page is turned into ready-made HTML at build time and served from Cloudflare's edge.

        Try the live API

        This request goes from your browser to the live WordPress site and returns its content as JSON. The app does the same thing at build time. Pick an example or edit the request yourself.
